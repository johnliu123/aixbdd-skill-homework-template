# 常見錯誤與 Anti-Patterns

每一項都給「症狀（怎麼從 Git/CI 證據看出來）→ 根因 → 改善建議」。偵測到這些狀況時，先用證據跟使用者說明現況，再提出方案；修復動作若涉及刪除他人分支、改寫歷史等高風險操作，一律先確認（見 [rules.md](rules.md#git-操作規則)）。

## 1. Shadow Branch + Cherry-Pick 混亂

**症狀**：`git log --all --graph` 看到多條長期存在、彼此有 cherry-pick 痕跡（相同 diff、不同 commit hash）的分支；功能之間互相依賴卻分散在不同分支上。
**根因**：團隊表面上說要做 TBD，但實際上還是用長期 feature branch 開發，事後才手動挑 commit 進 trunk，怕直接合併會弄壞 trunk。
**改善**：停止手動 cherry-pick，改成該分支直接、頻繁、小批次地合併回 trunk；如果怕壞，先補強 Stage 7 的自動化測試，而不是靠人工搬 commit 這種更容易出錯的方式。

## 2. Feature Flag 永遠不刪

**症狀**：程式碼裡有大量 `if (flag.enabled)` 判斷，對應的功能其實半年前就已經全量上線；`grep` flag 名稱時找不到任何「這個 flag 該在何時移除」的記錄。
**根因**：把「上線」當成任務終點，移除 flag 沒有被排進工作、也沒有 owner。
**改善**：把 flag 移除排進 Definition of Done；替每個 flag 標記類型（Release Toggle 應短命）與到期預期；定期（例如每個 Sprint 或每月）掃描超期未清理的 flag 並排入待辦。

## 3. 審查佇列化（PR 一放好幾天）

**症狀**：PR 開出後，`created_at` 到第一次審查留言之間常常超過 1 天；分支的 Git 年齡「看起來」不長，但實際是被審查卡住，不是被開發卡住。
**根因**：審查被當成「有空再看」的次要任務，而不是跟開發同等優先。
**改善**：把審查排進當天的優先事項（同步審查、輪值 reviewer、或配對編程直接互審）；PR 越小越容易快速審查，這也是為什麼要嚴格控制分支/PR 大小。

## 4. Trunk 被允許長時間紅燈

**症狀**：CI 歷史顯示 trunk 連續多次 build 失敗，中間還有新的 commit 疊上去。
**根因**：沒有人明確擁有「修好 trunk」這個責任，大家各自忙自己的事，覺得「反正之後會有人修」。
**改善**：引入明確的 Build Cop / 負責人機制（誰的 commit 弄壞就誰先處理，或輪值），並且在紅燈期間暫緩疊加新的合併，直到修好；這比事後花更多時間解一堆疊加問題便宜得多。

## 5. Big-Bang 資料庫變更

**症狀**：單一 PR 同時包含 schema 變更、資料搬移、應用程式邏輯切換，且沒有分階段的回滾路徑。
**根因**：把資料庫變更當成一般程式碼變更處理，忽略資料不可逆的特性。
**改善**：改用 Expand → Migrate → Contract 分階段落地（見 [rules.md](rules.md#exception-handling例外處理)），每個階段都是獨立、可回滾的小步驟。

## 6. 「整合週」/ 穩定化衝刺變成固定儀式

**症狀**：團隊排程中固定有一段「凍結期」或「穩定化 Sprint」，開發期間大家不太合併回 trunk，直到這段時間才一次性整合。
**根因**：把 TBD 應該天天做的整合工作，延遲累積到週期尾端，本質上退化成長期分支模式，只是分支換成了「大家各自本地/雲端暫存的一堆未合併變更」。
**改善**：拆解成每天都能小批次整合的工作方式；如果卡在測試環境或部署流程無法支撐高頻整合，優先修這個根本問題，而不是保留整合週當緩衝。

## 7. 沒有測試安全網就直接衝高合併頻率

**症狀**：合併頻率看起來很「TBD」，但幾乎沒有自動化測試，或測試覆蓋率明顯不足以攔截明顯錯誤。
**根因**：把 TBD 誤解為「Git 操作習慣」，忽略它背後需要自動化測試撐著才安全。
**改善**：先老實評估測試安全網夠不夠，不夠就先投資補齊最小可信的測試，再逐步拉高整合頻率；貿然衝高頻率只是讓壞狀態更快擴散到所有人。

## 8. 活躍分支數長期超過 3 條

**症狀**：`git branch -a` 排除已合併/已刪除後，長期同時存在 4 條以上活躍分支。
**根因**：多個功能平行長期開發、彼此互不整合。
**改善**：檢視這些分支能不能拆得更小、更快合併；平行開發的功能改用 Feature Flag 在同一條 trunk 上共存，而不是用多條分支彼此隔離。
